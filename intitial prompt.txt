## Prompt 1 of 5 — The Systems Architect

> **Role:** You are a Senior Platform Architect at a world-class mobile/web product company. I need you to architect a high-performance task management app for ADHD and visual learner users.

**Context:**
- Primary audience: Adults and teens with ADHD or visual learning preferences who struggle with traditional list-based task tools
- Core capabilities required: Task creation, visual urgency display (bubble view), list view, archiving, "For Later" bucket, cross-platform sync
- Technical priorities: RESPONSIVENESS, PERFORMANCE, ACCESSIBILITY, OFFLINE SUPPORT

**Produce a comprehensive technical blueprint including:**

1. **Information Architecture** — Complete sitemap with screen hierarchy and logical grouping (Main Board, For Later, Archived Tasks, Settings)
2. **User Journey Mapping** — Three critical paths: (a) creating a new task, (b) completing/archiving a task, (c) viewing and editing a saved task
3. **Data Architecture** — Full Firestore schema with entity relationships:
   - Task: `id`, `name`, `dueDate`, `forLater` (boolean), `details` (optional), `createdAt`, `status`
   - Settings: `expirationDays` (default 14), `dateFormat` (MM/DD/YYYY or DD/MM/YYYY)
4. **API / Logic Definition** — Required functions, Firestore rules, and real-time listener patterns
5. **Component Inventory** — Minimum 20 UI components with purpose definitions (e.g., BubbleCard, UrgencyRing, TaskModal, ListRow, SidebarNav, ToggleSwitch, etc.)
6. **Screen Blueprints** — Structural wireframe descriptions for each screen/template
7. **Technology Stack Recommendation** — Firebase/Firestore, framework, hosting, deployment pipeline
8. **Performance Benchmarks** — Target load times, animation frame rates (60fps bubbles), Core Web Vitals
9. **Accessibility Standards** — WCAG AA compliance, tap target sizing, colorblind-safe palette logic

Format this as a structured technical specification suitable for direct implementation inside Figma Make.

## Prompt 4 of 5 — The Interaction Systems Engineer

> **Role:** You are a Senior Frontend Systems Engineer. Architect the complete functional and interaction logic for the ADHD Task Board app's advanced interactive modules.

**[PASTE TECHNICAL SPEC + DESIGN SYSTEM + COPY FROM PROMPTS 1–3 HERE]**

**Required Modules:**

1. **Bubble View Engine** — Visual urgency display with dynamic sizing and animation
2. **List View Module** — Excel-style sortable rows with urgency bars
3. **Task Creation Modal** — Multi-field form with validation, date picker, and For Later toggle
4. **Sidebar Navigation** — Slide-out menu with route management
5. **Auto-Archive System** — Background job logic based on `expirationDays`

**For each module, define:**

- **State machine structure** (textual diagram: idle → loading → active → error → success)
- **Data flow** (props, events, Firestore listeners, optimistic UI patterns)
- **Bubble physics logic:**
  - Diameter formula: `baseDiameter + (maxBonus × urgencyScore)` where urgencyScore = inverse of days remaining
  - Float behavior: gentle CSS keyframe drift, collision avoidance with z-index layering
  - Pulse keyframe: overdue items pulse border opacity 0.4 → 1.0 at 1.5s interval
  - Most urgent bubble: centered, largest; others arranged radially by priority
- **List row logic:**
  - Row height scales with urgency (min 48px, max 120px)
  - Time-remaining bar: full width when >14 days, shrinks linearly to 0 at due date
  - Color matches urgency gradient from design system
- **Error management strategy** (Firestore offline, validation failures)
- **Loading behavior** (skeleton screens, not spinners — ADHD-friendly)
- **Empty state UX** (friendly illustration placeholder + CTA)
- **Edge case handling** (no due date on non-For Later task, past due archiving, duplicate names)

Then generate a React component architecture outline including hooks, handlers, and structural logic.

This will inform the complete interactive prototype build within Figma Make.
